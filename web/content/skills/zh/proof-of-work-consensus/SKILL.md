# 工作量证明与分布式共识

## 适用场景
- 实现或分析区块链共识
- 理解节点如何就交易历史达成一致
- 研究挖矿过程与区块验证
- 分析链的安全性和抗攻击能力
- 调整挖矿难度

## 核心概念

工作量证明（PoW）要求付出计算工作，才能向区块链添加区块。它让修改过去交易的成本很高，同时让验证保持低成本。

## 工作量证明的实现

1. **寻找有效的 nonce**：
   - 递增区块中的 nonce 值
   - 使用 SHA-256，对包含 nonce 的区块进行哈希计算
   - 重复此过程，直到哈希值具有所要求数量的前导零位

2. **工作量特征**：
   - 所需平均工作量随零位数量呈指数增长
   - 验证的计算成本很低，只需进行一次哈希运算

## 链的不可篡改性

1. **区块不可篡改性**：一旦付出满足 PoW 所需的 CPU 工作量，若不重做这些工作，就无法更改区块
2. **链的加固**：随着后续区块不断接在其后，更改一个区块需要重做该区块以及所有后续区块的 PoW

## 分布式共识：一 CPU 一票

1. **多数决策**：由最长链表示，也就是累计投入工作量证明最多的链
2. **IP 防护**：防止通过分配大量 IP 地址颠覆系统，与一 IP 地址一票不同
3. **安全条件**：如果多数 CPU 算力由诚实节点控制，诚实链的增长速度最快

## 攻击难度

要修改过去的区块，攻击者必须：
1. 重做目标区块的工作量证明
2. 重做所有后续区块的工作量证明
3. 追上并超过诚实节点的工作量
4. 随着更多区块被添加，追上的概率呈指数下降

## 难度调整

1. **目标**：每小时的平均出块数量
2. **机制**：近期出块时间的移动平均
3. **调整方式**：
   - 出块太快 → 提高难度
   - 出块太慢 → 降低难度

## 关键变量

- **Nonce**：为寻找有效哈希值而递增的数值
- **ZeroBitsTarget**：哈希值所需的前导零位数量
- **BlockHash**：将区块与 nonce 一起进行哈希计算得到的结果

## 输出

带有时间戳的区块被添加到最长链，代表网络达成的共识。

## 安全假设

该机制要求多数 CPU 算力由诚实节点控制，才能保证安全。
