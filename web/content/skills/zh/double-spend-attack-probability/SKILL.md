# 双花攻击概率

## 适用场景
- 根据确认次数计算交易安全性
- 确定接受付款前需要等待多少个区块
- 分析双花攻击风险
- 评估区块链安全参数
- 研究共识系统中的概率论

## 核心问题

计算落后 z 个区块的攻击者追上并覆盖诚实链，从而对某笔交易实施双花的概率。

## 关键参数

- **p**：诚实节点找到下一个区块的概率
- **q**：攻击者找到下一个区块的概率
- **z**：攻击者落后的区块数，即确认次数
- **假设**：p > q，诚实方占多数，拥有更高算力

## 计算方法

1. **对竞赛建模**：将其描述为二项随机游走
   - 成功事件：诚实链延长，领先优势 +1
   - 失败事件：攻击者的链延长，领先优势 -1

2. **赌徒破产问题**：计算从落后状态追上的概率
   - 如果 p ≤ q：概率为 1，攻击者最终会追上
   - 如果 p > q：概率为 (q/p)^z

3. **泊松分布**：考虑等待 z 次确认的时间
   - 计算期望值 λ = z × (q/p)
   - 攻击者可能取得的进展服从泊松分布

4. **最终概率**：使用求和公式计算，见参考资料

## 结果解读

- 随着 z，即确认次数增加，概率呈指数下降
- 例如：q=0.1，即攻击者拥有 10% 算力，且 z=5 时，P ≈ 0.0009
- 确认越多，安全性越高，且呈指数关系

## 安全最佳实践

1. **小额交易**：等待较少确认，例如 1-3 次
2. **大额交易**：等待更多确认，例如 6+ 次
3. **生成新密钥对**：收款人应在签名前生成新的密钥对，以防范预计算攻击

## 关键变量

- **p**：诚实节点找到下一个区块的概率，浮点数
- **q**：攻击者找到下一个区块的概率，浮点数
- **z**：攻击者落后的区块数，整数
- **λ**：攻击者可能取得进展的期望值，浮点数
- **k**：表示攻击者进展数量的变量，整数

## 输出

返回 0.0 到 1.0 之间的概率值，表示攻击者成功覆盖交易的可能性。数值越低，安全性越高。
