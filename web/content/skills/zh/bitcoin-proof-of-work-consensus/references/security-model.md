# 比特币共识安全模型

## 理论基础

### 计算上难以实现
比特币共识的安全性依赖以下原则：只要“诚实节点掌握多数 CPU 算力”，攻击者改变交易历史在“计算上就难以实现”。

### 无中心协调的简洁结构
网络以尽可能少的协调运行：
- 节点同时工作，彼此协调很少
- 节点无需表明身份
- 消息不必路由到某个特定位置
- 消息按“尽力而为”的方式投递

## 所有权与双花

### 数字签名框架
- 代币由数字签名构成
- 提供有力的所有权控制
- 无需可信第三方

### 防止双花
- 点对点网络记录公开历史
- 工作量证明使历史记录难以篡改
- 多数诚实 CPU 算力保证完整性

## 以 CPU 算力投票达成共识

### 投票机制
节点通过 CPU 算力表达共识：
- **接受**：继续扩展有效区块
- **拒绝**：拒绝在无效区块上继续工作

### 规则执行
共识机制可通过同一套投票过程执行任何所需的规则与激励。

## 安全属性

### 不可篡改性
- 交易历史随时间推移变得更加安全
- 每个新区块都会增加累计工作量证明
- 修改较早区块需要重做其后全部工作

### 容错能力
- 系统允许消息丢失
- 节点可以补取缺失区块
- 通过分叉处理应对网络延迟

### 抵抗攻击的能力
- 攻击者需要多数 CPU 算力才能成功
- 诚实算力占多数可保证网络完整性
- 攻击成本随网络增长而提高
