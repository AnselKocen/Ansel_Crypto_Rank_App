# 比特币工作量证明共识

实现比特币共识机制，通过工作量证明和基于 CPU 算力的投票，使无需信任第三方的电子支付成为可能。

## 适用场景

以下情况适用：
- 实现点对点电子交易网络
- 设计没有中央机构的分布式账本
- 防止数字货币系统中的双花
- 理解比特币节点如何达成共识
- 分析区块链系统的网络安全与完整性

## 前提条件

- 用于控制所有权的数字签名框架
- 已实现的工作量证明算法
- 网络中的诚实参与者掌握多数 CPU 算力
- 节点连接到点对点网络

## 网络运行

### 触发条件
以下情况触发网络处理步骤：
- 收到一笔新交易
- 找到一个工作量证明解

### 交易广播
1. 向所有节点广播新交易
2. 交易传播不要求立刻到达所有节点
3. 只要能到达足够多的节点，就足以保证最终被纳入区块

### 区块处理流程

1. **收集交易**
   - 每个节点将新交易收集到一个区块中
   - 准备用于工作量证明计算的区块

2. **寻找工作量证明**
   - 尝试为区块找到一个满足难度要求的工作量证明
   - 使用 CPU 算力求解密码学难题

3. **广播区块**
   - 找到工作量证明后，向所有节点广播区块
   - 区块广播允许出现消息丢失

4. **验证区块**
   - 只有全部交易有效时才接受该区块
   - 验证不存在双花交易
   - 拒绝无效区块

5. **扩展链**
   - 通过开始计算下一个区块，表达对当前区块的接受
   - 将已接受区块的哈希用作前一区块哈希
   - 这相当于用 CPU 算力为该链“投票”

## 共识规则

### 最长链规则
- 始终将最长链视为正确链
- “最长”指累计工作量证明最多
- 持续扩展最长链

### 分叉处理

当两个节点同时广播不同区块时：

1. **保留两个分支**
   - 在先收到的区块上继续工作
   - 保存另一个分支，以备其变得更长

2. **切换到更长的链**
   - 下一个工作量证明会扩展其中一个分支
   - 位于较短分支上的节点切换到较长分支

3. **补取缺失区块**
   - 如果节点错过某个区块，在收到下一个区块时请求补取
   - 通过比较前一区块哈希检测缺口

## 节点参与

### 离开与重新加入
- 节点可以随时离开或重新加入
- 重新加入时，接受工作量证明链作为事件发生的证明
- 无需在离线期间完成全部历史同步

### 共识投票
- 通过扩展有效链，用 CPU 算力投票
- 通过拒绝在无效区块上继续工作，否决无效区块
- 利用共识机制执行规则与激励

## 安全限制

- 攻击者不能控制多数 CPU 算力
- 网络延迟可能造成暂时分叉
- 消息可能丢失（系统具有容错能力）
- 随着工作量证明累积，历史记录变得不可篡改

## 输出结果

网络就一个有效区块达成共识，并扩展区块链，形成安全、不可篡改的公开交易历史。
