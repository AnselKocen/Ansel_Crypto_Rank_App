# SPV 安全分析

## 攻击方式

### 51% 攻击

如果攻击者控制网络中 >50% 的哈希算力：
1. 可以创建包含伪造交易的替代链
2. SPV 客户端可能将其作为最长链接受
3. 攻击者可以实施交易双花

### 防护策略

1. **等待确认**：确认次数越多，逆转所需难度越高，且呈指数增长
   - 6 次确认：覆盖该记录需要约 6 个区块的工作量
   - 每增加一次确认，攻击概率都会下降

2. **连接多个节点**：查询多个独立节点以检测不一致

3. **警报系统**：为无效区块实现点对点警报

## 确认次数要求

| 交易金额 | 建议确认次数 |
|-------------------|---------------------------|
| 小额（<$10） | 0-1 |
| 中额（$10-$1000） | 3-6 |
| 大额（>$1000） | 6+ |

## 内存需求

### 历史增长
- 2008：2GB RAM 足以存储区块头
- 增长速度：约 1.2GB/年（摩尔定律）

### 计算
```
headers_per_year = 6 blocks/hour × 24 hours × 365 days = 52,560
header_storage = 52,560 × 80 bytes = 4.2MB/year
```

### 实际规模
- 10 年的区块头：约 42MB
- 20 年的区块头：约 84MB
- 现代 RAM 容量可轻松容纳
